# 三只目标手完整模仿学习流水线 v1

## 目标与边界

这条流水线不是把已经训练好的 ShadowHand 权重直接交给三只目标手。每只手都有自己的观测维度、动作维度、归一化统计和整套模型；共享的是训练顺序与算法思想。训练输入来自该手重定向后、在统一 PhysX 中重放成功的轨迹。

最终顺序固定为：

`成功重定向轨迹 → 双 seed BC → BC Soup → 共享类别教师 → Task-ID 统一学生 → Online-R1 数据聚合 → Temporal3 → Diffusion 对照 → valid 选型 → test 一次`

旧项目只有 Bottle、Mug、Bowl、Camera 四类，可以训练四个完整类别网络。当前有 50 类、每类训练物体只有 8 条训练轨迹，而且 Linker 有 12 类没有成功训练轨迹，XHand/Wuji 各有 2 类。因此这里不训练 150 个容易过拟合甚至完全没数据的完整网络，而是每只手训练一个“共享观测主干 + 50 个类别残差头”的教师。它仍然按类别路由；有数据的类别学习自己的修正，无数据类别的残差为零，退回共享策略。

## 教师数据质量

官方成功要求物体抬升至少 0.10 m、水平漂移不超过 0.25 m，并连续维持 30 个 60 Hz 物理步。最终布尔公式没有显式要求接触，因此另做接触支撑审计：在上述合格抬升区间中，手物接触也必须连续存在 30 步。

训练划分审计结果：Linker 109/109、Wuji 270/270、XHand 255/256 条官方成功轨迹同时满足接触支撑定义。唯一 XHand 例外需要保留在异常表中；正式教师数据可以进一步排除它，但不能把重放失败轨迹伪装成专家。完整证据位于 `data/formal_v1/expert_quality_audit.json`。

## 各阶段内部数据流

### 1. 双 seed BC 与 BC Soup

两个同构单帧 BC 分别从随机 seed 20260813 和 20260814 训练。输入是当前目标手和物体状态、形状描述及 Task-ID，target 是该目标手重定向专家下一条绝对位置命令，loss 是标准化动作 MSE。随后逐参数等权平均得到 Soup，网络结构和推理成本都不变。等权是事先固定的，不用 valid/test 成败反调权重。

### 2. 共享类别教师

类别教师从 Soup 复制观测主干和共享动作头。BC 首层原本还读取 Task-ID embedding；转换时只复制观测列，类别 embedding 列有意舍弃。每类残差头严格从零开始，所以初始化时 50 类都等价于同一个通用策略。

训练时只用成功专家动作，并对有数据类别做反频率采样，避免某类成功 8 条、另一类只成功 1 条时前者完全支配梯度。教师的输出为“共享动作 + 当前类别残差”。

### 3. Task-ID 统一学生蒸馏

固定教师对离线 train/valid 每个状态生成动作标签。统一学生恢复为单个带 50 类 Task-ID embedding 的 MLP，推理时不携带 50 个教师头。主实验同时保留两个预先定义的监督目标：100% 教师动作，以及 70% 教师动作 + 30% 原专家动作；只通过 valid 冻结其中一个。

### 4. Online-R1（DAgger-like）

统一学生在 PhysX 中真正控制手，每类按确定顺序采一条训练轨迹，共 50 条。每一步先读取学生实际到达的状态，再让固定类别教师给出该状态下的动作标签；教师只标注、不控制仿真。之后按 25% 在线状态、75% 原离线数据微调学生一轮。

保存文件区分两种动作：`actions` 是教师监督动作，`executed_actions` 是学生实际执行动作。Temporal3 的历史必须用后者，否则相当于假设过去执行了教师动作，会形成训练泄漏。

这与严格 DAgger 的边界是：类别教师本身也是从有限重定向数据学得的近似 oracle，不是真人或规划器，所以准确称为 DAgger-like / online imitation，而不是拥有完美专家查询的理论 DAgger。

### 5. Temporal3

输入当前及前两步观测、前两步实际动作和 Task-ID，输出当前动作。网络从 Online-R1 单帧学生做无损初始化：旧观测权重放到“当前帧”列，历史观测/动作列初始为零，其余隐藏层和输出层完整复制。因此刚初始化时输出与 Online-R1 相同，训练后才学习短历史修正。

### 6. Diffusion Policy 对照

Diffusion 使用同一份离线 + Online-R1 聚合数据，读取三帧观测并生成未来 8 步动作片段，闭环只执行前 2 步后重新规划。它从头训练，因为去噪网络与 MLP 回归头不具备可解释的一一参数映射。Diffusion 的噪声 MSE 不能和 BC/Temporal 的动作 MSE直接比较，最终只比较同口径 PhysX 成功率。

## 为什么先做这些参数范围

- BC 第二 seed 完全复用已验证配置，避免把“多一个 seed”和“改超参数”混在一起。
- 类别教师学习率从 `3e-4` 降为 `1e-4`，因为主干已有 Soup 初始化，目标是小幅专门化；100 epoch、15 epoch 耐心足以覆盖小数据而不过度拖长。
- Student 用 `3e-4`，因为它是新建 Task-ID 统一结构；只比较 1.0 与 0.7 两个旧流程已有明确含义的教师比例，不做连续扫参。
- Online-R1 和 Temporal3 都用 `1e-4`，保护上一个阶段已经获得的能力；在线比例固定 0.25，直接复用旧项目协议。
- Temporal 主干保持 `[256,256,256]`，不是为了少参数，而是为了能从单帧学生严格继承。若改成 `[384,384,256]`，所谓“从 Online-R1 初始化”只能部分复制，实验解释会变差。

## 评测与停止规则

每阶段先看离线 loss、动作跳变和有限值，但这些只做故障诊断。闭环模型选择只用训练物体的 valid 轨迹，按每类最多一条形成 50 类均衡验证，主指标是类别宏平均成功率。若成功率相同，再比较轨迹成功率、平均最终抬升和平均接触步数。

每只手冻结唯一模型后，才在 50 个对象级未见物体的 500 条 test 轨迹上运行一次。不能查看 test 后回头选择 Student、Temporal 或 Diffusion，也不能取不同模型逐轨迹成功并集。

## 代码阅读顺序

1. `prepare/audit_expert_quality.py`：成功专家是否真的由接触支撑。
2. `prepare/make_model_soup.py`：BC 参数平均如何保证同构与可追溯。
3. `models.py` 中 `SharedCategoryExpertPolicy` 和两个初始化函数。
4. `prepare/generate_teacher_labels.py`：固定类别教师怎样生成离线蒸馏标签。
5. `dataset.py`：教师target与学生实际历史动作如何分开。
6. `evaluate_policy_isaac.py`：学生控制、教师只查询的单轨迹 Online-R1。
7. `prepare/aggregate_online_data.py`：在线数据如何汇总并交给 25/75 混合训练。
8. `train.py`：category teacher、student、online student、Temporal3 和 Diffusion 共用训练循环。

全部冻结超参数见 `configs/full_pipeline_v1.json`。长时间 PhysX 采集与评测仍由用户在终端运行，Codex只提供一次性可续跑命令。
