# ShadowHand Chunk8 主线：从零开始的代码与方法说明

这份文档只解释当前冻结方案，不再把所有失败尝试混在阅读路径里。读者不需要提前懂
灵巧手、模仿学习、DexRep或Isaac Gym。完整实验过程仍保存在仓库根目录
`PROJECT.md`，本文件负责回答“最终代码到底怎样工作”。

## 1. 我们在解决什么问题

环境中有一只Shadow Hand和一个待抓物体。每个episode开始时，手和物体处在给定初始
状态。策略每隔一个控制周期读取当前观测，输出28维动作，仿真器根据动作、碰撞、摩擦、
重力和PD控制推进一步。策略必须独立完成接近、闭合、抓稳和抬升。

测试时不能读取未来专家轨迹。专家轨迹只在训练时告诉模型“在这种状态下应该输出什么
动作”。这与重放专家轨迹有本质区别：重放知道未来70帧答案，自主策略只知道当前状态。

当前研究范围是GraspM3中的四类物体：Bottle、Mug、Bowl和Camera。一个共享策略处理
四类物体，类别通过4维one-hot提供。

## 2. 一个时间步里发生了什么

最终闭环可以压缩成下面七步：

```text
Isaac Gym给出2582维当前观测
        ↓ 固定裁剪
2460维 = 100维本体 + 1080维DexRep Sensor + 1280维DexRep PNL
        ↓ 三路编码
384维当前状态特征
        ↓ 拼接4维类别 + 前两步100维本体 + 前两步28维实际动作
644维动作网络输入
        ↓ 1024-1024-512-512 MLP
未来8步 × 每步28维动作
        ↓ 与过去7次动作块中指向当前时刻的预测等权平均
当前28维动作
        ↓ 第40到69步把腕部z补偿从0线性增至0.20，再裁剪到[-1,1]
Isaac Gym执行动作并产生下一帧
```

这里最重要的是“闭环”：下一步观测来自上一步动作造成的真实物理结果。如果手指没有按
预期接触物体，下一帧DexRep和本体状态会改变，策略有机会重新作出判断。

## 3. 原始数据是什么

GraspM3中一条Shadow轨迹有70帧，每帧28维：

```text
[0:3]   手腕世界位置 x、y、z
[3:6]   手腕XYZ欧拉角
[6:28]  Shadow Hand的22个手指关节目标
```

这些28维值经过正式数据流程转换成Isaac Gym使用的归一化PD目标。它不是力矩，也不是
关节速度。环境内部的PD控制器会努力让手跟踪目标位置。

每个原始物体文件还包含物体旋转矩阵和缩放。数据预处理会在Isaac Gym中放置物体和手，
计算每帧本体观测与DexRep，形成训练用观测—动作对。

70帧按20Hz控制频率对应3.5秒。最终评测先让策略自主输出70步，再固定第70步动作保持
52步，用于观察抓取是否继续维持，而不是让策略在训练时间范围外继续生成陌生动作。

## 4. 2582维观测与2460维输入

Isaac Gym的完整观测不只有关节角。它还包含关节速度、力、指尖状态、物体状态以及
DexRep。最终策略沿用旧主线的100维本体定义，删除122维速度和力字段：

- 28维手部关节速度；
- 28维关节力；
- 30维指尖速度；
- 30维指尖力；
- 6维物体线速度和角速度。

删除以后保留：

```text
100维本体状态
1080维 DexRep Sensor
1280维 DexRep PNL
= 2460维
```

代码入口是 `minimal_impl/model.py::filter_observation`。这个裁剪是固定索引，不是网络
学习出来的特征选择。

## 5. DexRep到底提供什么

只给网络关节角，网络知道“手指弯了多少”，却不直接知道指尖离物体表面多远、物体形状
怎样、手和物体处于什么相对关系。DexRep补充的正是动态手物几何。

本项目直接使用官方环境算出的两组DexRep特征，不在最小实现中重新发明几何算法：

- Sensor分支1080维；
- PNL分支1280维。

`DexRepEncoder`把100、1080、1280三路分别线性映射到128维。两路DexRep embedding做
L2归一化，使方向信息更稳定；本体embedding不做L2归一化，因为其数值幅度本身仍包含
有用的关节和位姿信息。三路拼接得到384维。

## 6. 为什么还提供类别ID

同样的几何状态在不同物体类别中可能对应不同抓取习惯，例如碗更偏向包覆边缘，杯子可能
需要避开把手。类别ID按照下面顺序编码：

```text
Bottle = [1,0,0,0]
Mug    = [0,1,0,0]
Bowl   = [0,0,1,0]
Camera = [0,0,0,1]
```

它不是每个物体一个ID，也不是记住某个实例。80个训练物体仍只共享四个类别编号。

## 7. Temporal3是什么

单帧观测很难判断运动趋势。两个状态看起来相近，但一个可能正在接近物体，另一个可能刚刚
滑离物体。Temporal3使用当前帧加前两步历史，因此总共涉及三个时刻。

历史包含：

```text
t-2的100维本体状态
t-1的100维本体状态
t-2真正执行的28维动作
t-1真正执行的28维动作
= 256维
```

episode刚开始没有过去动作，所以两步动作都置零，本体历史用首帧复制。推理时写入历史的
必须是经过时间集成的策略动作。正式评测器在模型历史更新以后才施加外部Z补偿，因此
历史不包含该补偿；最小实现也严格保持这一行为。

最终动作网络输入因此是：

```text
384维当前DexRep编码 + 4维类别 + 256维历史 = 644维
```

Temporal3不是RNN、GRU或Transformer，只是把固定两步历史直接拼接到MLP输入。

## 8. Chunk8是什么

普通BC在时刻t只预测动作a_t。Chunk8同时预测：

```text
[a_t, a_(t+1), ..., a_(t+7)]
```

每个动作28维，所以一个动作块共有8×28=224个数。网络主体仍是MLP，不是完整ACT的
Transformer或CVAE。实现中共享隐藏特征，原当前动作头输出第一步，新增未来头输出后7步。

动作块思想借鉴ACT的Action Chunking和Temporal Ensembling。我们没有照搬ACT网络，
而是把这两个思想接到现有DexRep-Temporal3 MLP上。长度8是本项目的工程选择：20Hz下
覆盖约0.4秒；16和32步候选在相同开发协议上更差。

## 9. 重叠时间集成怎样工作

假设策略已经运行到t=2：

```text
t=0预测：[a0^(0), a1^(0), a2^(0), ...]
t=1预测：          [a1^(1), a2^(1), ...]
t=2预测：                    [a2^(2), ...]
```

执行t=2动作时，有三个都指向t=2的预测：`a2^(0)`、`a2^(1)`和`a2^(2)`。最终配置
`decay=0`，因此直接取三者平均。运行到第8步以后，最多始终融合8个预测。

这里不是一次预测8步然后完全开环执行。每个时间步仍读取新观测、重新预测完整动作块，
因此依然是闭环策略。时间集成只是把多个时刻对同一动作的预测融合。

实现位于 `ChunkEnsembler.select`。必须在每个episode开始调用`reset`，否则上一条轨迹的
动作块会污染下一条轨迹。

## 10. 后期腕部Z补偿是什么

开发集诊断发现，一部分轨迹已经形成抓取，但后期抬升不足。最终推理从第40个自主动作起，
给28维动作中的第2维，也就是腕部z目标，增加逐步变大的补偿：第40步为0，第69步达到
0.20归一化动作量，然后整体裁剪到[-1,1]。

它不是0.20米。它是归一化动作空间中的0.20，实际位移由环境的动作上下界反标准化决定。
这个补偿没有改变手指动作，只给抓取后半段增加一致的向上趋势。

## 11. 训练样本怎样构造

数据有两个来源。

离线样本来自成功示范轨迹：

- 当前观测来自专家轨迹；
- 历史动作来自专家真正执行的动作；
- `demo_action_chunk`是原始GraspM3后续8步；
- `teacher_action_chunk`是四个类别教师对这些状态给出的动作。

在线样本来自旧学生在仿真中的闭环访问状态：

- 当前观测来自学生rollout；
- 历史动作是学生真正执行的动作；
- 教师只给访问状态贴监督标签，不推进环境；
- 在线状态没有一条天然对应的原示范未来，因此示范块和教师块使用同一纠正标签。

训练采样时离线占75%，在线占25%；每个来源内部再做类别均衡。这样不是简单把两个文件
拼起来，因为在线文件帧数可能更多，直接拼接会让它淹没离线示范。

`FrameDataset`还会给100维本体观测加入`[-0.05,0.05]`均匀噪声。该0.05是归一化/当前
字段数值上的幅度，不应解释成所有物理量的5%。这是继承的最终训练设置，而不是理论最优。

## 12. 动作块末端怎样处理

轨迹第68帧只能找到第68、69帧真实动作，后面6个位置没有标签。数据集为保持固定形状，
会用末动作补齐，但同时产生布尔mask：

```text
[True, True, False, False, False, False, False, False]
```

损失只读取True位置，因此补齐动作不会冒充真实未来标签。这一点很重要：旧开发过程中曾
发现末帧标签错位，当前最小实现明确用mask避免动作块越过episode。

## 13. 损失函数是什么

每个有效28维动作的基础损失为：

```text
2 × 手腕平移MSE
+ 手腕姿态MSE
+ 22维手指MSE
+ 全部28维动作L1
```

手腕平移乘2，是因为少量位置误差就可能让整只手错过物体。L1对较大误差的增长比MSE慢，
与MSE组合可兼顾平滑小误差和异常样本鲁棒性。

动作块损失等于第0步损失加后7个有效未来步损失的平均。随后分别对原示范块和教师块计算：

```text
总损失 = 0.80 × 原示范动作块损失 + 0.20 × 类别教师动作块损失
```

在线样本中两者相同，所以仍等价于教师纠正损失。这里没有actor-critic、PPO或奖励函数，
最终训练本质上是监督模仿学习。

## 14. 网络参数与优化

最终动作MLP为：

```text
644 → 1024 → 1024 → 512 → 512 → 28
                              ↘ 196（未来7×28）
```

隐藏层使用ELU。优化器是Adam，学习率`2e-5`，batch size 128，共训练4轮；真正锁定的是
第2轮checkpoint，因为训练loss继续下降时闭环物理成功率反而退化。选模型必须看Isaac Gym
成功率，不能只看回归loss。

## 15. 训练与推理的区别

训练时：

- 可以读取未来8步专家动作作为监督目标；
- 可以读取类别教师生成标签；
- 所有动作块都直接用于计算loss；
- 不需要让每个batch在仿真里执行。

测试时：

- 只能读取当前观测、自己保存的两步历史和四类ID；
- 不读取未来专家动作；
- 不检索参考轨迹；
- 每步重新预测动作块，只执行集成后的当前动作。

“训练时有未来标签”与“测试时读取未来轨迹”不是一回事。普通监督学习也会在训练时读取
答案，关键是部署时模型只能依赖允许输入。

## 16. Isaac Gym怎样执行28维动作

`minimal_impl/simulate.py`负责真实闭环：

1. 读取物体轨迹文件中的初始任务；
2. 用官方`ShadowHandGraspDexRepIjrr2`创建并行环境；
3. 重置环境并取得2582维观测；
4. `PolicyRuntime.act`生成当前动作；
5. `task.step(action, step)`把动作送入官方环境；
6. PhysX计算碰撞、关节运动和物体运动；
7. 循环70次，然后保持末动作52步；
8. 汇总官方成功标记和抬升诊断。

因此视频和成功率来自真实Isaac Gym物理环境，不是仅在NumPy数组上比较轨迹误差。

## 17. 成功率口径

最终报告主指标采用仓库官方成功标志，并对物体先分别算成功率，再做物体宏平均。宏平均
防止轨迹更多的物体在总成功率中占据过大权重。

同时保留“稳定官方成功”副指标：官方条件需要在末段持续满足，且峰值到终点回落不超过
3厘米。它用于区分短暂抬起和较稳定保持，但不替代主指标。

最终8个物体、每个seed共216条轨迹，使用2025、2026、2027三个物理seed。最终方法：

- 官方物体宏平均：`39.56% ± 0.34%`；
- 官方轨迹总体平均：`42.75%`；
- 稳定官方成功平均：`39.04%`。

## 18. 消融实验说明了什么

| 方法 | 官方物体宏平均 |
|---|---:|
| 仓库发布BC | 2.46% |
| 同80物体公平训练的官方BC | 6.76% |
| Temporal3 | 12.05% |
| Temporal3 + Demo80 | 11.60% |
| Chunk8但不执行时间集成 | 15.16% |
| Chunk8 + 等权时间集成 | 36.02% |
| Chunk8 + 等权时间集成 + Z补偿 | 39.56% |

不能把全部提升归因于“预测8步”。只加未来动作头、不进行重叠执行时只有15.16%；真正的
主要增益来自把重叠动作块用于当前动作平均，净增20.86个百分点。后期抬升再增加3.54点。

## 19. 最小实现各文件负责什么

### `model.py`

- `filter_observation`：2582→2460；
- `DexRepEncoder`：2460→384；
- `Chunk8Policy`：644→8×28；
- `HistoryBuffer`：管理前两步历史；
- `ChunkEnsembler`：重叠预测等权平均；
- `PolicyRuntime`：组合历史、集成和抬升补偿；
- `action_loss/chunk_loss`：训练目标；
- `load_project_checkpoint`：读取冻结Lightning checkpoint。

### `data.py`

- `TrajectoryBatch`：统一离线和在线轨迹；
- `FrameDataset`：逐帧样本、历史、未来块和mask；
- `balanced_sampler`：四类平衡及25%在线采样。

### `project_data.py`

- 从真实预处理NPY加载离线轨迹；
- 从在线NPZ恢复学生rollout；
- 保持轨迹边界和帧顺序。

### `train.py`

- 建DataLoader；
- 执行80%示范、20%教师的Chunk8监督；
- 保存简洁checkpoint。

### `prepare.py`

- 对同结构BC做参数Soup；
- 用四个类别教师为离线状态生成路由标签。

### `simulate.py`

- `evaluate`：官方Isaac Gym闭环评测；
- `collect`：学生推进环境，教师只贴标签的在线数据采集。

## 22. 当前方法的边界

这套方法显著超过仓库BC和旧Temporal3，但39.56%仍不是高成功率。主要边界包括：

- 类别ID只覆盖四类，不是开放世界类别识别；
- 仍是确定性回归，难以完整表达同一观测下多种正确抓法；
- 在线教师不是真正从任意偏离状态恢复的强oracle；
- 0.05统一噪声并没有严格按物理单位设计；
- Z补偿是开发集校准的固定启发式，不是根据接触状态自适应；
- 成功率对物理接触边界和仿真seed仍有波动；
- 训练集覆盖、DexRep质量和专家动作质量共同限制泛化上限。

因此正确结论是：在同一Final8和三seed协议下，动作块重叠时间集成带来了可靠的大幅提升；
不能进一步声称该方法解决了通用灵巧抓取，也不能把训练loss下降当作物理成功。
