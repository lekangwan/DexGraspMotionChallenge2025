# 阅读前先建立整体认识（零基础入口）

## 0.1 这个项目最后做成了什么

先用一句不带术语的话概括：

> 数据集里原本只有 Shadow Hand 的抓取动作。我们先把这些动作“翻译”成三种不同机器手能执行的动作，并在物理仿真中筛出真正抓得住的轨迹；然后再让神经网络学习在执行过程中根据物体状态修正手指动作。

项目现在已经完成两个阶段：

1. **基础重定向已完成**：三只目标手都完成正式 1000 条轨迹的生成和 30 cm 稳定抓取评测。
2. **进阶策略已完成**：BC、Temporal3、Diffusion、PhaseResidual、DAgger 和 Residual PPO 都已训练和闭环评测；最终方法是 Residual RL。

当前已经不是“还在选择方法”的阶段，而是**整理报告、视频、答辩材料和代码解释**的阶段。最终结果速查见附录 A，实验原始过程以 `WORK_LOG.md` 为准。

## 0.2 先区分四种容易混在一起的东西

这是阅读整个项目最重要的表格：

| 名称 | 它是什么 | 是否已经通过物理验证 | 是否由神经网络产生 |
|---|---|---:|---:|
| Shadow 源轨迹 | 数据集提供的“原手怎么抓” | 数据集认为成功 | 否 |
| 目标手候选轨迹 | 重定向算法翻译出的“新手应该怎么动” | 否 | 基础方法中否 |
| 目标手专家轨迹 | 候选在 Isaac Gym 中稳定抓起并通过质量门 | 是 | 否 |
| 闭环策略轨迹 | 神经网络根据当前状态逐步发出的动作 | 需要重新评测 | 是 |

因此，“重定向完成”不等于“策略训练完成”，而“几何优化成功”也不等于“物理抓取成功”。本项目的完整链路是：

```text
Shadow源轨迹
    ↓ 运动学重定向
目标手候选轨迹
    ↓ Isaac Gym物理重放
通过稳定与运输门的专家轨迹
    ↓ 监督学习或强化学习
目标手闭环策略
    ↓ 再次在Isaac Gym评测
最终策略成功率
```

## 0.3 什么叫“灵巧手”“自由度”和“动作”

**灵巧手**可以理解为安装了多个可控关节的机器人手。它与普通二指夹爪的区别是：夹爪通常只控制“张开/闭合”，灵巧手可以分别改变拇指、食指、中指等关节，从而形成包络抓、捏取、侧抓等不同手型。

**自由度（DOF）**就是能够独立控制的运动量。例如，一个只能弯曲的手指有 1 个自由度；既能弯曲又能左右摆动，则至少有 2 个。自由度越多，通常越容易模仿复杂手型，但控制和优化也更复杂。

本项目把一帧动作分为两部分：

```text
[手腕6维, 手指关节若干维]
```

手腕 6 维是三维平移 `(x,y,z)` 加三维旋转 `(roll,pitch,yaw)`。手指维度取决于具体机器手，所以 Shadow、Linker、XHand、Wuji 的一帧动作分别是 28、12、18、26 维。

这里的动作不是 torque，也不是速度，而是**位置控制目标**：程序告诉 Isaac Gym“下一时刻希望每个关节到达这个角度”，仿真器内部的 PD 控制器再产生力，把关节拉向目标。

## 0.4 什么叫“重定向”

重定向不是简单复制关节角。原因是两只手的骨骼长度、关节数量、旋转方向和机械耦合都不同：Shadow 食指有多个独立关节，但 Linker 一根手指可能只有一个电机并通过机械联动带动两个关节。直接复制数字没有物理含义。

更准确地说，重定向是在回答：

> 已知 Shadow 在这一帧的掌心、指尖和指节位于哪里，目标手的手腕和关节应该取什么值，才能尽量形成相同的抓取功能？

对第 `t` 帧，输入是 Shadow 动作 `s_t`，未知量是目标手动作 `q_t`。程序用目标手 URDF 做正向运动学，计算 `q_t` 对应的掌心和指尖位置，然后不断调整 `q_t`，直到它们尽量接近 Shadow 的目标几何关系。求出的 `q_t` 就是这一帧的重定向结果。

这个过程与训练 MLP 不同：

- 没有跨轨迹共享、通过训练积累的网络权重；
- 每一帧都现场求一个带关节边界的最优化问题；
- 上一帧解只作为下一帧的初始猜测，使求解更快、更连续；
- 下次处理新轨迹时复用的是同一套目标函数和超参数，不是上一条轨迹的动作答案。

## 0.5 一条轨迹在时间上到底有多长

GraspM3 一条源轨迹有 70 帧，频率为 20 Hz，因此数据本身持续：

```text
70 ÷ 20 = 3.5 秒
```

Isaac Gym 物理仿真以 60 Hz 运行，所以一个源数据帧会在线性插值后执行 3 个物理步：

```text
70帧 × 3物理步 = 210个运动物理步
```

末尾再保持最后一个动作 30 个物理步，即 0.5 秒，用来检查物体会不会滑落。因此真正计入成功曲线的是 240 步、4.0 秒。开始前还有 30 个物体落稳步，即 0.5 秒，但这部分不属于抓取动作，也通常不录入视频。

```text
落稳0.5秒（不计抓取） → 执行3.5秒 → 末端保持0.5秒
```

所以“70 帧”和“240 步”并不矛盾：前者是 20 Hz 的动作数据，后者是 60 Hz 的物理执行记录。

## 0.6 为什么需要把整条轨迹交给手，而不是只给起点和终点

导航任务常能用“起点—终点”描述目标，但抓取不是只关心最终姿态。手必须按正确时序经历：

```text
在物体外张开 → 接近物体 → 手指闭合形成接触 → 保持抓形 → 手腕抬升
```

如果只给最终手型，手指可能在接近前就闭合、从错误方向撞飞物体，或者根本无法到达目标手型。整条轨迹同时规定了**空间路径**和**动作时机**。进阶策略的价值，就是在保留这一基本任务进度的同时，根据真实接触和物体滑移做闭环修正。

# 第一部分：基础重定向任务

## 1. 任务定义

**任务**：把 Shadow Hand（仿真人手，22 个手指关节）的 1000 条成功抓取轨迹，重定向到三只结构不同的机器手（Linker O6 / XHand / Wuji），在 Isaac Gym 物理仿真中重放，以"稳定抬升 30 cm"为成功判据。

**硬约束**：

- 数据规模固定：50 类、100 物体、1000 轨迹，抽样 seed 和清单冻结可复现
- 指标是物理成功率，不是几何误差（反复验证过：关键点误差小的轨迹不一定抓得住）
- 测试集与调参集分离（调参只在 calibration/开发集，正式 1000 只在方法冻结后碰）

## 2. 三只目标手的选择与结构

### 2.1 选择标准与决策

| 候选 | 主动自由度 | 决策 | 理由 |
|---|---|---|---|
| Linker O6 | 6 | ✅ | 低自由度、强欠驱动代表——研究"信息极限压缩下能否保留抓取功能" |
| XHand | 12 | ✅ | 参考仓库唯一完整基线——先跑通全链路的中等难度基准 |
| Wuji | 20 | ✅ | 高自由度、形态接近 Shadow——研究"高保真重定向上限" |
| Allegro | 4 指 | ❌ | 不符合"五指灵巧手"字面要求 |
| Revo3 | 21 | ❌ | 超过 20 主动自由度上限 |

三只手构成**自由度梯度实验**（6→12→20），核心研究问题之一："自由度从 20 降到 6，重定向误差和物理成功率如何变化？"

### 2.2 各手结构细节

**Shadow Hand（源手）**——22 个手指关节：

- 食指/中指/无名指：各 4 关节 = 侧摆(±0.349 rad) + 屈曲×3(0–1.571)
- 小指：5 关节 = 侧摆×2 + 屈曲×3
- 拇指：5 关节 = 旋转(±1.047) + MCP 屈曲(0–1.222) + 侧摆(±0.209) + 侧摆(±0.524) + 远端屈曲(-1.571–0，**负号方向**)
- 轨迹格式 (T,28) = [平移3, 欧拉3, 关节22]

**Linker O6**——6 电机带 11 手指关节：

- URDF 中 5 个 mimic 联动（如某关节 = 另一关节 × 1.86 / × 0.89 倍率）
- Isaac 中实际 17 DOF = 虚拟手腕 6 + 手指 11
- 优化只做 6 个主动量，mimic 在模型内部展开（`expand_linker_frame`）
- 保存格式 (T,12) = [腕6, 主动6]

**XHand**——12 关节：

- 拇指 3：bend [0,1.832] + rota1 [-0.698,1.570] + rota2 [0,1.570]
- 食指 3：bend(侧摆) [-0.174,0.174] + joint1/joint2 [0,1.919]
- 中指/无名指/小指：各 2 个屈曲 [0,1.919]
- 保存格式 (T,18) = [腕6, 关节12]

**Wuji**——20 关节 = 5 指 × 4：

- 普通指布局：[MCP 屈曲 0–1.636, 侧摆 ±0.495, PIP 0–1.627, DIP 0–1.627]
- 拇指 4 关节：屈曲 [−0.045,1.651] / [−0.166,0.934] / [−0.493,1.627] / [−0.493,1.627]
- 保存格式 (T,26) = [腕6, 关节20]

## 3. 数据来源（逐字段）

### 3.1 源轨迹 GraspM3

每物体一个 npy：

```
{
  "grasp_seqs": (20, 70, 28),  # 20轨迹×70帧×28维；70帧@20Hz=3.5秒
  "obj_rotmat": (20, 3, 3),    # 物体世界旋转（整条轨迹固定）
  "obj_scale":  (20,),         # 物体缩放
}
```

`.npy` 是 NumPy 保存数组的二进制格式。这里它保存的是一个 Python 字典，而不是一张图片或一个模型。若 `grasp_seqs.shape=(20,70,28)`，含义是该物体有 20 种抓取演示，每种演示有 70 帧，每帧是 28 个控制量。

第 `i` 条轨迹必须与 `obj_rotmat[i]` 和 `obj_scale[i]` 一起使用：前者告诉程序物体在世界中朝向哪里，后者告诉程序网格应放大或缩小多少。它们不是每帧变化的状态，而是该条抓取的固定初始化条件。

坐标约定：源平移以 `[0,0,1]` 为参考点，程序统一做 z 方向对齐。不同手和不同参考代码可能使用不同基座原点，所以“数值相同”不一定代表世界中的实际位置相同；这也是必须校准手腕变换的原因。

### 3.2 物体模型 COACD

物体网格切成凸块（`coacd/decomposed.obj`），物理引擎用凸块算碰撞。开发集物体在 `reference/.../object_41/`，正式集在 `external_data/meshdata/`。

可以把视觉网格理解为“物体看起来是什么形状”，把碰撞网格理解为“物理引擎认为哪里能撞到”。复杂凹形网格直接做碰撞很慢，COACD 把它近似拆成若干凸块，既保留主要形状，又让 PhysX 更容易计算接触。

### 3.3 URDF 与正向运动学

所有方法的第 0 步：解析 URDF → 拿到关节名/边界/mimic → 建立 FK 模型（给定关节角算任意 link 上点的世界坐标）。XHand/Wuji 用 `get_penetraion_keypoints`（每手预定义的关键点集合），Linker 用 `linker_world_points`（link 局部坐标 + 全局手腕变换 + scale）。

**URDF** 是机器人的结构说明书，记录“哪个 link 连接哪个 joint、关节绕什么轴转、能转多少、mesh 放在哪里”。**link** 是一段刚性骨骼，**joint** 是两段骨骼之间的运动连接。

**正向运动学（FK）**的输入是所有关节角，输出是手掌、指尖等位置。它回答“已知怎么弯，手指在哪里”。重定向需要反过来寻找关节角，因此本质上是一个带约束的逆运动学问题；代码没有直接求解析逆解，而是让 SLSQP 反复调用 FK，并根据位置误差迭代调整关节。

关键点不是模型自动理解的“食指尖”语义，而是我们事先在每只手的某个 link 局部坐标中标出的点。例如 Shadow 食指尖必须对应 XHand 食指尖，不能误对应到中指或关节中心。关键点可视化校准就是为了在大批运行前发现这种语义错误。

### 3.4 冻结清单 manifest

- **50 集筛选集**：train50（SHA-256 排序选 50 类各 1 条，不读物理标签）/ confirm_e
- **正式 1000 集**：formal_50c_100o_1000t_seed20260808.json（每类 2 物体 × 10 轨迹）
- 筛选纪律：任何新方法先 50 集评估，绝不直接上 1000（贵）；正式集只在方法冻结后评测

manifest 是一份 JSON 清单，明确指定物体名、源文件、轨迹索引、资产路径和文件哈希。它本身不存轨迹，只是回答“这次实验到底评哪些样本”。冻结 manifest 的意义类似考试前封卷：方法不能因为已经看到某些轨迹成功或失败，就悄悄换成更有利的样本。

本项目虽然基础方法没有神经网络参数，也仍然需要开发集和测试集分离。因为关键点、loss 权重、接触阈值、夹紧量等人工选择，本质上也会对开发样本过拟合。

## 4. Pipeline 五步（每步输入输出）

```
①读数据      ②重定向（核心）        ③物理重放           ④评测              ⑤配对比较
.npy+URDF → 逐帧优化出候选轨迹  →  Isaac真执行   →  成功/失败+失败分类 →  逐条对比统计
```

- **②重定向**：输入源轨迹 (70,28) + 目标手 URDF → 输出候选 (70,D)（D=12/18/26）。逐帧求解（见 §6）
- **③物理重放**：CPU PhysX、dt=1/60、substeps=2、每源帧执行 3 步（20Hz 动作）、PD 控制（刚度 120 阻尼 5）驱手指、落稳 30 步后开始、末动作保持 30 步
- **④评测**：见 §5
- **⑤配对比较**：同一批轨迹上新旧方法逐条对比 → "新增 N/丢失 M/净变化 + McNemar exact p"

**核心原则：候选 ≠ 专家**。数学优化出来的轨迹只是"候选"；物理重放成功抬起的才是"专家轨迹"。

配对比较不是只看两个总成功率。例如旧方法 10/50、新方法也 10/50，可能是同样 10 条成功，也可能新方法新增 10 条同时丢掉旧方法 10 条，稳定性含义完全不同。程序把每条轨迹分成“共同成功、共同失败、新增、丢失”四类；McNemar 检验主要比较新增与丢失是否明显不对称。

以 Linker 的一条轨迹为例，程序中的对象依次变化为：

```text
源数组 grasp_seqs[i]          (70, 28)
        ↓ retarget_linker_*.py
目标候选 grasp_seqs[j]        (70, 12)
        ↓ expand_linker_frame
Isaac实际位置目标              (每步17维：腕6+真实手指11)
        ↓ PhysX接触仿真
物体位置/接触/实际关节曲线     (240步)
        ↓ compute_success_metrics
一条JSON报告：success、最高高度、最终高度、接触等
```

这里的 PD 控制器可以直观理解为“带阻尼的弹簧”：位置误差越大，关节越用力追向目标；阻尼抑制高速震荡。我们输出的是目标位置，真正的接触力由控制器和 PhysX 根据质量、摩擦、碰撞共同产生。

**Isaac Gym 不等于一定使用 GPU。**基础重放代码通过 `create_cpu_sim` 明确使用 CPU PhysX，以保证三手评测口径一致；是否使用 GPU 是仿真参数，而不是由“导入了 Isaac Gym”自动决定。进阶 PPO 的神经网络在用户的 RTX 4060 上用 CUDA 训练，但当前通用环境的接触仿真仍走 CPU PhysX。网络设备和物理设备是两件不同的事。

## 5. 评测协议（stable 30cm v2，逐条）

物体相对落稳初态抬升 ≥ 0.30 m，且**最后 30 个物理步**同时满足：

| 门 | 阈值 | 作用 |
|---|---|---|
| 高度保持 | 末 30 步全部 ≥ 0.30 m | 排除"瞬间过线" |
| 回落 | 峰值→末段 ≤ 0.03 m | 排除"抓起又掉" |
| 波动 | 末段高度震荡 ≤ 0.01 m | 物体在手里要稳 |
| 接触 | 末段接触比例 = 100% | 排除"抛起来" |
| XY 漂移 | ≤ 0.25 m | 排除"撞飞" |

**运输质量门**（进阶任务的入场券）：末段物体相对手掌的滑移/转动要小——通过它才是"可用专家"。
**手型解剖门**：四普通指远端关节不得反向弯折（视频审查+关节审计触发，详见 §8）。

这里的“抬升 30 cm”不是看物体世界坐标是否大于 0.30，而是计算：

```text
当前物体z − 落稳后初始物体z ≥ 0.30 m
```

这样大物体和小物体即使初始中心高度不同，也使用同一抬升距离。`success` 是整条 episode 的布尔结果，不是“成功帧占多少”。只要末段稳定门有一项失败，这条轨迹就计为失败。

“稳定成功”和“运输质量”是两层筛选。193/1000 表示 Linker 有 193 条达到稳定 30 cm；其中只有 153 条进一步满足相对手掌滑移要求，所以进阶训练使用 153 条，而不是把全部 193 条都当高质量专家。

**口径教训**：早期用 10 cm 判据跑完了全部正式实验，后经用户指正改为 30 cm 并全量重算——**评测口径必须开工第一天锁死**。

## 6. 绝对关键点法（所有方法的公共基线，实现细节）

**变量**（每帧）：[目标手关节 D-6, 手腕平移3, 手腕欧拉3]（内部布局；保存时转回 [腕6, 关节]）。
**目标函数**（每帧）：Σ 语义点对 (FK点 - Shadow目标点)² × 1000（15 对语义点：掌心、四指近端/中段/指尖、拇指中段/指尖）。
**求解**：nlopt LD_SLSQP，逐帧独立求解、上一帧热启动、首帧零位或对齐初值；maxeval 50–100，xtol_rel 1e-6，ftol_rel 1e-8。
**边界**：关节 URDF 上下界（Wuji 再叠加解剖配置），平移 ±2 m，欧拉 ±π。
**为什么逐帧而不是整段**：70 帧联合优化变量 70×(D) 维、SLSQP 不可行；逐帧+上一帧热启动+时序正则 ≈ 平滑轨迹，成本可控。

把公式翻译成直白语言：假设这一帧有 15 对对应点。对每一对，程序计算目标手点与 Shadow 点之间的三维距离，距离越大，loss 越大。SLSQP 尝试改变目标手关节和手腕，让总 loss 下降，同时不允许关节超过 URDF 边界。

一次迭代的内部过程是：

```text
给出一组目标手关节角
    ↓ FK
算出15个目标手世界关键点
    ↓ 与Shadow关键点作差
得到loss和梯度
    ↓ SLSQP更新变量并执行边界约束
重复，直到收敛或达到maxeval
```

“上一帧热启动”只表示第 `t` 帧从 `q_(t-1)` 附近开始找，不表示直接复制上一帧。这样既利用动作通常连续的事实，也避免每帧从完全张开的随机位置重新搜索。

`maxeval=50` 表示单帧最多评估目标函数约 50 次，不是训练 50 个 epoch。`xtol_rel` 和 `ftol_rel` 分别控制变量变化与 loss 变化多小时认为收敛。

**关键发现（后续所有方法的出发点）**：绝对点法的"低 loss"不保证"抓得住"——Wuji v2 关键点误差 1.965 mm 却比 11.821 mm 的 v1 成功率低（12/20 vs 16/20）。**几何相似 ≠ 抓取功能**。

## 7. 三手最终方法（实现级细节）

阅读下面三手方法前，先区分四种约束各自在管什么：

| 约束 | 直观问题 | 它直接保证什么 |
|---|---|---|
| 绝对关键点 | “目标手的点是否到了源手点的位置？” | 几何位置接近 |
| 功能向量 | “掌心到指尖的方向和相对长度是否相似？” | 跨手形态关系 |
| 接触锚 | “应该接触物体的指尖是否真的靠近接触区域？” | 接触位置 |
| 抓握偏置 | “低自由度手是否弯得足够紧？” | 闭合程度 |

它们都不能单独保证抓取成功，因为物理成功还取决于摩擦、接触法向、力矩、碰撞和执行时机。最终方法是根据不同手的机械结构选择不同组合，而不是强求三只手使用完全相同的 loss。

### 7.1 XHand：官方参考基线（最终）与向量+α（最强挑战者）

**官方基线**：参考仓库实现（SLSQP + 15 点匹配），视频审查通过。正式 1000：516 稳定 / 501 运输。

**向量+α 方法（探索中最好，50 集 32/50 vs 官方 27/50）**：

向量法不要求两只不同形态的手把中间骨节硬放在相同世界坐标，而是比较“从掌心指向指尖”的箭头。箭头方向描述手指朝向，长度比描述展开程度；零姿态尺度比先吸收两只手天生的长度差异。

目标函数逐项（归一化单位下）：

```
L = Σ_i w_i·Huber(‖v_i(q) - scale_i·v̂_i‖, 0.02)  位置向量 ×1000
  + Σ_j w_j·Huber(‖û_j(q) - û̂_j‖, 0.5)            方向向量
  + 1000·‖palm(q) - palm̂‖²                        掌心锚定
  + 0.0025·‖joints‖²                               中性正则
  + 0.01·‖joints - joints_prev‖²                   时序
```

- **位置向量 10 条**：掌心→指尖×5（权重 1.0）+ 掌心→中段×5（权重 0.5）
- **方向向量 5 条**：中段→指尖单位方向（权重 5.0）——专门防止"指尖位置对但指向错"的退化
- **scale_i**：两手零姿态（全张开）对应向量长度比自动计算——Shadow 手指短、目标手长时自动放大，免人工调
- **α 捏合混合**（AnyDex 核心思想）：每帧量源手拇指尖到各指尖距离 d，

  ```
  α = clip((0.05 - d)/(0.05 - 0.025), 0, 1)
  指尖权重 ×= α + (1-α)×0.6；方向权重 ×= α + (1-α)×0.5
  ```

  d ≤ 2.5cm（捏合中）→ 该指尖权重拉满；d ≥ 5cm（张开）→ 放松跟踪。**闭式计算，不加优化维度**。
- **Huber(δ=0.02)**：误差超 2cm 后线性计——防止个别不可达目标霸占梯度

**为什么 50 集赢、正式集输（461 vs 516）**：50 集每类只 1 条轨迹，正式集每物体 10 条（轨迹索引 0–9 抓取风格差异大）；α 权重对源手拇指-指尖距离敏感，在未见轨迹风格上不稳定。**教训：开发集赢家必须经过正式集验证**——这是本项目第二个"开发集赢家未泛化"案例。

### 7.2 Linker：向量v2 + α + 接触锚 + 抓握偏置 + 热启动（最终，193/153）

6 DOF 单技巧不够，四组件叠加（每个都有消融增量）：

**组件 1：分指段向量 + α**（配置 `linker_anydex_vectors_v2.json`）
Linker 手指两段式：位置向量 = 掌心→指尖×5（w1.0）+ 掌心→近端×4（w0.5）+ 掌心→拇指中段（w0.5）；方向 = 近端→指尖×5（w5.0）；α 混合同 XHand。

**组件 2：接触锚（+2 条）**
诊断：向量法忠实复现源手屈曲量，但 Linker 手指更长，源手"轻捏"能拿住的物体 Linker 必须"用力包住"——失败轨迹接触步数只有成功者的 1/3。
实现：**闭合阶段**，把源手**正在接触物体的指尖世界位置**（接触掩膜：指尖到物体表面 < 0.02 m）当钉子：

```
L += 3.0 × mean(‖tip_target(q) - anchor_source‖²) × 1000
```

只对掩膜内的指尖生效。规律：**只在 6 DOF 有效**——12/20 DOF 手的向量解本来就能把指尖放对，硬钉反而过约束（XHand 8/50、Wuji 28/50 判负）。

“锚”不是物体上的实体钉子，而是 loss 中的目标位置。程序从 Shadow 轨迹判断哪些指尖已经进入物体表面 2 cm 邻域，再要求目标手对应指尖靠近这些位置。它提供接触线索，但不直接计算抓力，所以仍需 PhysX 验证。

**组件 3：抓握偏置（+2 条）**
单侧屈曲拉力，目标剖面取自夹紧法的闭合姿态 `[1.16, 0.58, 0.94, 1.26, 1.46, 1.54]`：

```
L += 8.0 × mean(relu(target_joint - joint)²)
```

**relu 的含义**：只惩罚"弯得不够"，绝不惩罚"弯得更多"。权重扫描：5 太弱（11/50）、8 最优（13/50）、接触 5 回落（12/50）。只在闭合+抬升阶段激活。

例如目标屈曲角是 1.2 rad：当前只有 0.7 rad 时产生惩罚，当前已经是 1.3 rad 时惩罚为 0。它不是把所有轨迹变成同一个固定手型，而是给欠闭合解设置一个单侧“最低抓紧倾向”。

**组件 4：热启动**：首帧从夹紧法已生成的闭合姿态开始，避开"手指半开"局部最优。

**阶段检测**（自动，源数据驱动）：指尖距物体表面 < 0.02 m 且 ≥2 指 → 闭合帧；手腕升高 0.03 m → 抬升帧；接触检测无解时 `fallback=nearest`（用最近接近帧回退，7/50 条轨迹依赖）。

这里的阶段不是人工固定为“第 30 帧闭合”。不同轨迹的接近速度不同，所以程序从该轨迹自身的指尖—物体距离和腕部高度推断。`fallback=nearest` 只在整条源轨迹没有满足严格双指阈值时启用，选择最接近接触的帧，并写入元数据以便审计。

### 7.3 Wuji：旧无约束点法（最终，581/557）+ 三处"外科手术"记录

**最终采用**（用户决策，成功率优先）：15 点逐帧 SLSQP，无解剖约束。代价：四指反向弯折（利用 URDF -28° 负向范围"掰手指"包物体，末段 92.5% 时刻低于 -5°）和拇指过早弯成 90°（96.1% 帧）。**报告如实披露**。

“无解剖约束”不代表没有任何关节边界，而是仍使用原 URDF 边界；问题在于 URDF 允许普通指远端关节向反方向转约 28°。数学优化把这个合法数值范围当作可用动作，但它视觉上不像自然人手，也可能不适合真机长期执行。

**我们做的三处修复（作为消融保留）**：

1. **解剖约束 coupled_flexion**：PIP/DIP 下界 -28°→-5°，软约束 DIP≈2/3×PIP（w0.02），并同步写入物理仿真。结果：手型合规但 581→431（反弯抓取的"非法收益"约 150 条被去掉）
2. **拇指零空间修复（n005）**：删掉错的"拇指中段绝对对应"，只保指尖位置一条硬信息，在 4 个拇指关节的零空间里用中性正则(0.05)+时序(0.01)选自然解。90° 帧 96.1%→2.6%，指尖偏移 <3mm，train50 34/50（+5）
3. **phase_open 分阶段闭合**：接近阶段拇指保持展开、接触前 8 帧开始闭合（lead=8/settle=4）。手型完美（90° 帧 0%）但成功率 13→12→30/50 一路小降——**早闭合其实是"承力提前量"**。按成功率优先放弃，作消融

# 第二部分：进阶任务

## 0. 从“轨迹重放”到“策略控制”

基础任务中，控制器提前拿到了整条 70 帧目标手轨迹，只需按时间顺序播放。它不会观察物体滑没滑，也不会因为实际关节落后而改变下一步动作，因此叫**开环重放**。

进阶任务训练的是策略 `π`：每一个物理步都读取当前观测 `o_t`，再输出动作 `a_t`。执行后环境变成新状态，策略继续观察并决策：

```text
观察当前状态 o_t → 策略输出 a_t → PhysX执行 → 得到 o_(t+1) → 再决策
```

这叫**闭环控制**。它理论上能在物体滑动或关节没有跟上时修正动作，但也会出现新问题：策略自己的一个小错误会改变下一步输入，错误可能逐步累积。

### 0.1 监督学习和强化学习在本项目里的区别

监督学习把专家动作当标准答案：

```text
输入：专家执行时的观测
标签：专家下一动作
loss：预测动作与专家动作的差
```

BC、Temporal3、PhaseResidual 和 Diffusion 都属于这一大类。训练数据已经告诉模型“正确动作是什么”，网络通过反向传播降低 MSE 或扩散噪声预测误差。

强化学习不要求每一步都有专家标签，而是让策略在环境里执行，根据结果得到奖励：抬得更高、有接触、最终成功会得到正奖励，动作残差过大会扣分。PPO 根据这些经验增加高奖励动作的概率。最终 Residual RL 同时利用两者：专家轨迹提供基础动作，RL 学习其上的闭环修正。

### 0.2 本项目的策略不是相机输入

观测来自仿真真值，包括关节位置/速度、物体三维位姿和速度、接触数及网格形状描述。这类观测通常称为**特权状态**：非常适合研究控制算法，但真实部署时不能凭普通 RGB 相机直接得到，必须由视觉姿态估计、触觉或状态估计器替代。

所以当前结果证明的是“在准确仿真状态下的目标手控制能力”，不是完整的视觉到动作系统，也不是 sim-to-real 已完成。

## 1. 任务定义

基础任务筛选出的专家轨迹，训练**闭环操作策略**：策略每物理步读状态、出动作，从"手指全张开"的初态开始，自己完成接近—闭合—抬升。比较三类模型：单帧 MLP（BC）、三帧历史（Temporal3）、Diffusion Policy；并探索 PhaseResidual（增量+相位）与 Residual RL（PPO 残差）。

**与基础任务的关键区别**：基础任务"重放"专家轨迹（开环）；进阶任务策略**闭环**执行——每一步的动作依赖当前状态，误差会累积。

最终 Residual RL 还必须写清一个边界：它不是只输入物体状态就从零规划抓取，而是每个测试任务仍提供该轨迹的重定向基线命令，并采用专家手腕轨迹；策略只学习手指残差。因此它更准确地叫“参考轨迹条件下的闭环修正策略”。

## 2. 数据链路（专家池 → trace → split）

**专家池**（重放成功 + 运输质量达标）：

| 池 | 运输质量轨迹数 |
|---|---:|
| xhand_official | 501 |
| linker（新方法） | 153 |
| wuji_old（旧无约束） | 557 |
| wuji_n005（修复版） | 421 |

**Wuji 两池并存的实证设计**（本项目最重要的方法学设计之一）：旧无约束轨迹被"手型门"（人工视觉标准）隔离为 0 条可用专家。用户质疑：**这是视觉定义，没有训练实证**。于是两套池分别训练、分别评测——用策略成功率回答"反弯轨迹到底能不能当专家"。

**Trace**：每条轨迹重放时保存逐物理步（240 步 = 70帧×3 + 30 保持）的"**执行前状态 → 下一条命令**"对。修复过一次**未来泄漏 bug**：初版在 PhysX 推进后记录状态却与刚执行的命令配对（动作后状态配过去动作），离线 loss 虚低但闭环语义错误；修正为每步先读状态再写命令，并加元数据标签 `trace_alignment=pre_action_state_to_command_v1` 防混用。

一条监督样本不是整段视频，而是一对向量。例如第 100 个物理步：输入记录“命令执行前手在哪里、物体在哪里、有没有接触”，标签记录“接下来应发什么关节位置目标”。240 步轨迹就产生约 240 对样本。

**对象级划分**（无泄漏）：每类 2 个物体——一个物体只进 train/valid（8+2 条），另一个物体 10 条全部进 test。策略从未见过 test 物体。归一化统计只从 train 算。

不能把同一物体的不同帧随机分到 train 和 test。那样模型虽然没见过第 101 帧，却已经见过同一个网格、同一抓取方向的前后帧，测试会虚高。对象级划分要求测试物体实例整体不可见，才是在测同类别新物体泛化。

## 3. 第一代：绝对动作回归（BC / Temporal3 / Diffusion）——为什么全灭

三个模型都输出**绝对关节角度**。12 个模型（3 模型 × 4 池）闭环评测**全部 0/500**。

**BC（Behavior Cloning）**就是把控制问题改写成普通回归：给网络当前观测，让它预测专家下一条绝对命令，使用 MSE 训练。Temporal3 在此基础上多看当前和前两步状态；Diffusion 不直接回归一个均值，而是从噪声逐步生成未来动作片段，希望表达“同一状态可能有多种合理动作”。

它们离线 loss 低只能说明“在专家访问过的状态上，输出接近专家”。真正闭环时模型访问的是自己造成的状态。假设第一步手指角度只差 0.02 rad，下一步观测就已不完全属于训练分布；模型再犯一个小错，偏差继续扩大。这就是**distribution shift（分布偏移）**和**compounding error（复合误差）**。

**诊断过程**（这是本部分最重要的方法论示范）：
1. 单条 rollout 看指标：策略相邻命令跳变 L2 均值 **1.51**，专家 **0.049**——**31 倍**
2. 手在动但物体不动：平均接触仅 0.49 步——手在物体上方乱舞，从未碰到
3. 根因：**闭环分布偏移下的绝对动作失稳**。训练时模型见到的都是专家状态；闭环里第一步的微小误差改变状态 → 模型输出跳变到另一个"动作模式" → 状态更偏 → 恶性循环

**尝试过的缓解都失败**：观测噪声增强（v5，腕部变成单调下降）、动作限速（允许步长仍是模型跳变的量级）。**结论：绝对动作回归在这个任务上不是调参能救的**。

## 4. 第二代：PhaseResidual（增量动作 + 相位）

**架构**（模型、数据集、运行时三处配套）：

- **预测目标**：增量 δ = command_t − command_{t−1}（归一化：(δ − δ_mean)/δ_std，统计从 train 算）
- **输入**：当前观测 + **上一条实际命令**（归一化）+ **相位** phase = t/209（0→1，210 个运动步）+ 类别 ID
- **执行**：command_t = command_{t−1} + δ（积分）；首步上一命令 = 张开姿态
- 模型：MLP（观测 68/66 维 → 增量 D−6 维），150 epoch 早停

为什么预测增量更稳定？绝对回归每一步都要重新回答“关节应该位于多少度”，相邻输入稍变就可能跳到另一个绝对姿态；增量回归只回答“在上一条真实命令上再动多少”。专家在 60 Hz 下相邻变化本来就很小，因此学习目标集中在零附近，动作自然连续。

相位 `phase∈[0,1]` 是归一化任务进度。0 表示刚开始，接近 1 表示运动结束。单看某一帧状态，策略可能分不清“正在接近”还是“已经抬升”；相位提供一个确定的时序坐标。它不是从传感器推断出来的隐状态，而是由当前物理步编号直接计算。

**效果**：跳变 1.51 → 0.026（比专家还平滑）、接触 0.49 → 25–170 步。但抬不起物体——引出下面的修复链。

## 5. 修复链：五个补丁（每个都有归因和消融数字）

| # | 问题（诊断证据） | 修复 | 效果 |
|---|---|---|---|
| 1 | 手指在接近阶段提前闭合（第 20 步手指已 1.1 rad，专家保持 0） | **相位感知增量钳位**：10 个相位 bin，每 bin 每维取专家增量 P95 作上限；接近段手指限幅 ≈0.0001，闭合段自动放开到 0.26–0.48 | 手指时序对齐专家 |
| 2 | 闭环抬腕消失（离线给专家状态时模型正确预测 +0.0024/步，闭环里只有 +0.0001） | **DAgger**（见 §6） | 抬腕恢复 |
| 3 | DAgger 第一版无效 | **关键 bug：在线样本的"上一条命令"从教师标签推导**，而不是学生真实执行命令——模型学不到"从自己的状态纠偏"。数据集支持独立 previous_commands 字段 | DAgger 真正生效 |
| 4 | 腕部横向漂移（专家 y 恒 0.127，模型漂到 -0.028，差 15 cm） | **层级分解**：腕部走专家开环（相位对齐的专家帧），策略只学手指 | 漂移消除 |
| 5 | 评测口径错误（调试的轨迹专家自己只抬 1.3 cm） | **专家成功子集**：只在专家重放成功的轨迹上计复现率 | 口径公平 |

**每个补丁的教训都通用**：①时序结构可以"查表"强加，不必让网络学；②复合误差要用 DAgger 而非数据增强；③管道 bug 靠"结果与预期完全一致"这种反常信号发现；④确定性成分不该进学习目标；⑤先检查任务本身是否可能。

## 6. DAgger（实现细节）

**流程**（每轮）：
1. 学生（当前模型）在 50 条 train 轨迹上闭环 rollout（每类 1 条），记录每一步的（观测、学生执行命令）
2. **教师标注**：用**相位对齐的专家命令**（完美 oracle，确定性）：phase p 的专家标签 = 专家轨迹第 round(p×69) 帧
3. 合并：离线样本 + 在线样本（各池 +12000 步），在线样本的 previous_commands = 学生真实执行命令、监督 actions = 教师（专家）命令
4. 重训 → 下一轮

**为什么用相位专家而不是学习式教师**：旧项目的类别教师在闭环里自身振荡（历史诊断），不能当 oracle；相位专家零失稳且与我们的相位设计天然对齐——比标准 DAgger 的"学习式教师"更强。

DAgger 与普通 BC 的区别不在于 loss，而在于**去哪里采输入状态**。普通 BC 只在专家状态上训练；DAgger 让学生真的跑起来，哪怕学生跑偏，也在这些跑偏状态上查询教师答案。模型因此学到“已经偏了以后怎样拉回来”。本项目的教师不是实时求解新抓法，而是根据当前相位从同一条专家轨迹取对应命令，所以它是 DAgger-like 的确定性 oracle。

**轮次结果**：第 1 轮大幅提升（Linker 3.7%→12.3% 等）；第 2 轮 Linker 继续涨（12.3%）但 XHand 回落（19.1%→8.6%）——**DAgger 轮次振荡**（第二轮学生状态聚在第一轮行为附近，重训过拟合采集分布）。处理：每池保留最优轮次。

## 7. Residual RL（最终方法，实现细节）

**为什么 RL 能赢 BC**：BC 家族无论怎么增强，都在"专家分布"上训练、"自己的分布"上执行；RL 在自己的探索分布上训练，天然对闭环偏移鲁棒。

### 7.1 一步内部到底发生什么

以 XHand 为例，某个物理步先从专家候选取出 18 维基线命令。PPO 不重新输出完整 18 维，而只输出 12 个手指关节残差：

```text
expert_command = [腕6, 手指12]
policy_residual = [手指残差12]
final_command = [expert腕6, expert手指12 + residual12]
```

Linker 输出 6 维手指残差，Wuji 输出 20 维。残差经过 `tanh` 限制在 `[-1,1]`，再与基线手指命令相加并裁剪到 URDF 关节边界。训练初始标准差为 0.05，因此一开始主要在专家动作附近探索，而不是随机乱动整只手。

评测时不再随机采样，而使用高斯策略的均值并经过 `tanh`，所以同一观测得到确定性残差。

**环境**（`train_residual_ppo_general.py`，三手通用）：
- 20 env 并行（每条轨迹一个 env），240 步/回合
- 基线 = 专家轨迹（含腕部）；策略输出**手指残差** f（动作维 = 手指数 6/12/20），command = 专家帧 + 残差，经 mapper 映射到物理 DOF 布局
- **观测（逐字段）**：基线命令(D) + 实际关节位置(dof) + 关节速度(dof) + 物体相对位移(3) + 四元数(4) + 线速度(3) + 角速度(3) + [log1p(接触数), 相位, 相对z](3) + 上一步残差(f) + 物体形状描述(14 维：轴向尺寸3+顶点协方差6+表面积+体积+径向分位数3)
- **奖励**：200×max(抬升增量, −0.002) + 0.02×[有接触] + 末步成功 +10 − 0.002×‖残差‖²

观测维度不是三只手完全相同，因为 `command_dim`、物理 DOF 数和残差数不同。代码按以下公式自动计算：

```text
obs_dim = 基线命令D
        + 实际关节位置dof
        + 实际关节速度dof
        + 物体位姿与速度13
        + 接触/相位/相对高度3
        + 上一步手指残差f
        + 形状描述14
```

奖励中的“抬升增量”是相邻物理步物体高度的变化，而不是当前总高度。这样每一步向上移动都能立即获得反馈，不必等到最后才知道好坏；最终严格成功再奖励 10，保证策略仍以完整任务成功为目标。残差惩罚让策略倾向于只在必要时偏离专家。

### 7.2 Actor、Critic 和 PPO 分别做什么

Residual RL 使用的是 Actor-Critic：

- **Actor**读取观测，输出每个手指残差的高斯分布均值；训练时从分布采样以探索。
- **Critic**读取同一观测，估计“从现在开始预计还能获得多少累计奖励”。
- **Advantage**比较实际回报与 Critic 预期，判断这次动作比预期更好还是更坏。

如果 advantage 为正，PPO 会提高该动作在相似状态下的概率；为负则降低。PPO 不允许新策略一次改变过猛，而是把新旧动作概率比裁剪到 `1±0.2` 附近。这就是“Proximal（近端）”的含义：每轮只走相对保守的一步，减少强化学习突然崩溃。

GAE 用 `γ=0.99` 把未来奖励折算回当前，并用 `λ=0.95` 在高方差的真实回报和有偏的价值估计之间折中。每轮 20 个并行环境各执行 240 步，得到约 4800 个 transition，再做 4 个 epoch、每 epoch 4 个 minibatch 的网络更新。

### 7.3 CPU、GPU和并行环境的真实关系

`train_residual_ppo_general.py` 中 Actor、Critic、rollout batch 和 PPO 反向传播通过 `--device cuda` 放在 RTX 4060 上。20 个 Isaac Gym 环境也在同一个 simulator 中并行推进，但当前 `create_cpu_sim` 明确采用 CPU PhysX；Isaac Gym 是框架名称，并不自动意味着 GPU PhysX。

本项目实际测得 20 env 规模约 2.8 秒/轮，网络很小、CPU 接触仿真占主要时间，所以仅把网络放 GPU 与 CPU 总耗时接近。若要进一步利用 4060 加速物理，需要把 PhysX 切到 GPU pipeline，并把逐环境 `get_actor_*`/接触读取改成 tensor API；这属于性能工程，不改变 PPO 方法本身。

### 7.4 最终结果能说明什么、不能说明什么

54.1% 或 54.3% 表示：在**专家自身成功的测试轨迹**中，Residual RL 有约一半能够在未见物体实例上复现稳定抓取。它证明参考轨迹附近的物理闭环修正比纯 BC 更有效。

它不能证明策略已经学会：

- 只给一个目标物体就自主选择抓取方向；
- 不依赖测试轨迹的专家基线命令；
- 自主规划手腕路径；
- 从相机图像感知物体；
- 直接迁移到真实机器手。

这些边界不削弱当前结论，但必须在报告和答辩中主动说明，避免把“参考轨迹跟踪与修正”夸大成“端到端通用抓取”。

**PPO**：tanh 压缩高斯（σ=0.05）、GAE(γ=0.99, λ=0.95)、4 epoch × 4 minibatch、clip 0.2、target_kl 0.5、lr 3e-4、grad clip 1.0、300 轮。

**学习回路 bug（重要答辩素材）**：初版 KL 早停检查在"下一批更新前"——第一个 minibatch 更新后，后续每个 minibatch 的更新前 KL 都超阈值被拒，**每轮实际只做 1/16 次更新**，且报告的 clip_fraction 恒 0、approx_kl≈0、value_loss 卡在 7–9——"训练在空转但日志看起来像在学"。修复：KL 检查移到更新后测量。修复后 value_loss 6.2→1.0 收敛、clip_fraction 0.38 健康。

## 8. 评测口径（三层，报告必须严格区分）

1. **全量 test（500 条）**：含专家自己失败的轨迹——策略在这些任务上必败。RL 全量：XHand 144/500、Linker 60/500、Wuji旧 151/500、Wuji修复 83/500
2. **专家成功子集**：只在专家重放成功的轨迹上计"策略复现率"——策略学习能力的纯净度量（分母：XHand 257、Linker 81、Wuji旧 295、Wuji修复 190）
3. **训练集 vs 测试集**：RL 训练集 40–45% 曾被误读为"远超旧项目 26%"——**训练集是背答案**；测试集（36–54%）才是泛化。答辩被问"你的 40% 和之前的 26% 怎么比"，答案就在这层区分

例如 XHand 全量 test 是 500 条，其中只有 257 条对应的专家基线自身成功。Residual RL 在全量上成功 144 条，即 28.8%；在专家成功子集上约为 54.1%。前者回答“随机测试任务总体能完成多少”，后者回答“在参考轨迹本身可行时，策略能复现多少”。两个指标都真实，但回答的是不同问题，不能只挑较大的一个报告。

## 9. 最终结果与分析

**统一测试集口径（专家成功子集复现率）**：

| 专家池 | BC 式最优 | Residual RL | 提升 |
|---|---:|---:|---:|
| XHand | 19.1% | **54.1%** | 2.8× |
| Linker | 12.3% | **54.3%** | 4.4× |
| Wuji 旧方法 | 12.9% | **45.4%** | 3.5× |
| Wuji 修复版 | 11.6% | **36.3%** | 3.1× |

**分析**：

1. **RL 全面碾压 BC**（3.1–4.4×）：闭环分布鲁棒性是进阶任务的第一性原理
2. **Linker 受益最大**（4.4×，54.3% 追平 XHand）：6 DOF 欠驱动手最依赖闭环纠错——基础任务里它最弱（193），进阶任务里 RL 几乎抹平差距
3. **Wuji 两池：旧方法 45.4% > 修复版 36.3%**，且三种口径（RL 训练集、RL 测试集、BC 测试集）一致——"反弯轨迹当专家可用"被训练实证支持。**人工视觉标准对仿真成功率没有预测力**，这是本项目最重要的方法学结论
4. **Temporal3 消融**（用户的疑问）：在 PhaseResidual 上加三帧历史，XHand 13.2%（无历史 19.1%）、Linker 6.2%（3.7%）、Wuji 两池基本持平——**相位输入已经提供了"第几步"的时序信息，历史冗余**；只有 6 DOF Linker（观测信息最少）受益。结合旧项目"历史只在最后的 Temporal3 阶段有效"：**历史记忆只在策略基本正确、需要平滑抗噪时有效**
5. **与旧项目 26% 的对比**（诚实口径）：RL 的 XHand 全量 28.8% 与旧项目 Final8 26.15% 同量级，但本设定更有利（专家腕部开环 + 专家基线输入）——报告必须写明这个边界

## 10. 进阶任务的困难清单（答辩故事线）

1. 12 模型全 0 → 31× 跳变诊断 → 增量+相位架构
2. 五个补丁链（§5）——每个都有归因和数字
3. PPO 学习回路 bug——"指标正常但没在学"的经典陷阱
4. 训练集数字误读风险——口径纪律
5. Diffusion+专家腕部仅 1.2%——绝对动作的振荡问题在开环片段下依然存在（Diffusion 输出的是绝对动作片段）

# 第三部分：答辩问答预备

> 按"被问概率 × 答不上来的尴尬程度"排序的常见问题与回答要点。

**Q1：为什么用向量而不是绝对关键点？**
A：绝对点匹配假设两只手的中间骨节一一对应，但手的长短/关节数不同，硬凑位置会折出不自然的形状；且"位置对"不保证"功能对"（Wuji v2 误差 2mm 反而抓不住）。向量只匹配"掌心到指尖的方向+长度关系"（按零姿态长度比缩放），把"手长得不一样"这个事实吸收进尺度里。α 混合进一步让"捏合时指尖精确、张开时姿态自然"自动切换。

**Q2：α 混合的 α 是怎么算的？为什么不直接学？**
A：闭式计算：α = clip((0.05 − d)/(0.05 − 0.025), 0, 1)，d 是源手拇指尖到该指尖的距离（单位米）。d ≤ 2.5cm 是捏合、≥ 5cm 是张开。不学的原因：它从输入直接可算，学反而增加参数且不稳定。这个设计来自 AnyDexRetarget 的捏合自适应权重。

**Q3：接触锚为什么只在 6 DOF 有效？**
A：自由度够的手（12/20）向量解本来就能把指尖放在正确位置，强制拉到源接触点反而过约束（XHand 14→8、Wuji 32→28）。6 DOF 的 Linker 指尖放不准，接触锚提供额外的闭合信息（+2）。这是一个"信息补足"与"过度约束"的权衡，由数据决定边界。

**Q4：抓握偏置为什么用 relu 单侧？**
A：relu(target − joint) 只惩罚"弯得不够"，不惩罚"弯得更多"——已经弯够的解不受影响，只把欠闭合的拉向专家闭合剖面。双侧平方会把自然弯得更多的解也拉回来。

**Q5：相位钳位的 bin 怎么定的？会不会限制策略能力？**
A：10 个 bin，每 bin 每维取专家增量 P95 作上限（下限 1e-4）。它限制的是"每步最多动多少"，不是"总共动多少"——总位移由积分决定，不受限。它消灭的是"该静止的阶段乱动"（接近段手指增量≈0）。副作用：它假设专家时序是对的——这正是相位设计的含义。

**Q6：DAgger 里为什么用相位专家当 oracle，而不是学习式教师？**
A：旧项目的历史诊断发现类别教师闭环自身振荡，不能当 oracle。相位专家（专家轨迹按相位对齐）零失稳、确定性，且与我们的相位设计天然一致。这比标准 DAgger 更强（oracle 更可靠），也更容易实现。

**Q7：你们 DAgger 的"上一条命令"bug 到底怎么回事？**
A：在线样本的训练格式需要 (obs, prev_command, phase → delta)。第一版把教师标注的命令当作"上一帧命令"推导 prev（即 prev = 教师命令平移）——这等于假设学生上一帧执行的就是教师命令，**丢了"学生真实执行了什么"这个纠偏信号**，DAgger 退化成普通重放。修复：数据集中独立存学生真实执行命令作为 previous_commands。

**Q8：RL 的 40% 和旧项目的 26% 怎么比？**
A：不可直接比。40% 是训练集（背答案）；26% 是旧项目 Final8 未见物体宏平均。可比的口径：RL 统一测试集全量 28.8%（XHand）——同量级，但我们的设定更有利（专家腕部开环+专家基线输入）。报告里三层口径全部列出，不混用。

**Q9：PPO 学习回路 bug 是什么？怎么发现的？**
A：KL 早停检查放在"更新前"——第一个 minibatch 更新后，后续 minibatch 的更新前 KL 超阈值被跳过，每轮只做 1/16 次更新；且报告指标采自更新前（clip_fraction 恒 0、approx_kl≈0 的假象）。发现途径：value_loss 卡在 7–9 不收敛 + clip_fraction 恒 0 两个"不可能"的指标。修复：KL 检查移到更新后。

**Q10：为什么 Wuji 最终用旧无约束方法？**
A：成功率优先（581 vs 431）。旧方法的反弯/拇指问题是视觉缺陷，不影响仿真成功率——而且进阶任务的训练实证（RL 口径 45.4% vs 36.3%）证明这些轨迹当专家数据更好。**人工视觉标准对仿真成功率没有预测力**，修复版作为消融保留。

**Q11：为什么评测要分"专家成功子集"？**
A：test 集里有一部分轨迹专家重定向本身就失败（比如某 ball 轨迹专家只抬 1.3cm）——策略在这些任务上必败。混在一起会低估策略的学习能力。专家成功子集是"策略复现率"的公平分母；全量数字也报告（含"不可能任务"）。

**Q12：层级分解（专家腕部开环）会不会被质疑"不是端到端"？**
A：会，但这是有意的工程决策：腕部轨迹由源轨迹确定，是确定性成分，不该进学习目标（漂移 15cm 的实验证明了学习它的代价）。策略学的是真正需要适应性的部分（手指抓形）。这是"把确定性成分开环、把适应性成分闭环"的层级控制思想，报告中明确标注边界。

**Q13：手型门（解剖约束）到底该不该要？**
A：这是本项目最有意思的开放问题。仿真里"掰手指"是有效策略（+150 条），真机上可能不可行。我们两边都做了（约束版 431、无约束版 581），并用训练实证（Wuji 两池对比）给了一个答案：**在当前仿真评测口径下，无约束更好**。如果评估关注真机迁移，约束版是更安全的选择——报告把两边都摆出来。

**Q14：Temporal3 为什么最后阶段加历史才有效？**
A：历史的作用是"平滑和抗单帧噪声"——前提是策略已经基本正确（旧项目里 Temporal3 在 Online-R1 之后）。早期策略本身是错的，给历史也没用。我们的 PhaseResidual 用相位输入提供了"第几步"的时序锚点，历史与之冗余——所以我们的消融里历史基本无增益（除 6 DOF Linker）。

### 推荐代码阅读顺序

如果完全从零开始，不建议先钻进最长的优化脚本。按下面顺序，每一步只回答一个问题：

1. `retargeting/evaluate/linker_replay_utils.py`：12 维 Linker 命令怎样展开成 17 个物理 DOF。
2. `retargeting/evaluate/isaac_replay_common.py`：一条已经生成的轨迹如何执行和判成功。
3. `retargeting/evaluate/replay_linker_isaac.py`：把前两步组合成一个完整场景。
4. `retargeting/run/retarget_linker_vectors.py`：候选轨迹本身如何逐帧求出来。
5. `retargeting/run/run_linker_vector_manifest.py`：一条命令如何扩展到整份 manifest。
6. 再平行阅读 XHand/Wuji 的 `retarget_*` 与 `replay_*`，理解三手差异。
7. `advanced_policy/observations.py` → `dataset.py` → `models.py` → `train.py`：理解监督策略。
8. `advanced_policy/evaluate_policy_isaac.py`：理解训练模型怎样进入真正闭环。
9. 最后读 `advanced_policy/residual_ppo.py` 和 `train_residual_ppo_general.py`：理解最终 RL 方法。

在阅读任何函数时，都用同一个检查表：输入的数组 shape 是什么、输出 shape 是什么、单位是什么、这一步会不会读取未来专家信息、结果是否经过物理验证。
