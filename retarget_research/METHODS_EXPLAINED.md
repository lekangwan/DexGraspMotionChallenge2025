# 三手重定向方法详解（零基础版）

> 本文面向完全不了解本项目的读者，从数据、概念到每一只手的最终方法逐层讲清楚。
> 读完本文，你应当能回答：数据长什么样、重定向到底在算什么、三只手的三个方法为什么长这样、结果是怎么评判的。

---

## 1. 我们要解决的问题

**一句话**：把一只"人手"（Shadow Hand）的成功抓取动作，翻译给三只结构完全不同的机器手，让它们在物理仿真里真的把物体抓起来、抬起来。

**为什么要"翻译"而不是"复制"**：三只目标手的关节数量、手指长度、驱动方式都和源手不同：

| 手 | 主动自由度（电机数） | 特点 |
|---|---|---|
| Shadow Hand（源） | 22 个手指关节 | 仿真中的人类手，抓取轨迹由官方数据集提供 |
| Linker O6 | **6** | 严重"欠驱动"：一个电机带动多个关节（mimic 联动），信息极度压缩 |
| XHand | 12 | 中等自由度，参考实现最完整 |
| Wuji Hand | 20 | 最接近 Shadow 的形态，手指各有 4 个关节 |

自由度越少，翻译越难：22 个关节的动作要"压缩"进 6 个电机，必然有信息损失——这也是本项目的研究问题之一：**自由度从 20 降到 6，成功率会怎么变？**

**成功标准**（唯一硬指标）：在 Isaac Gym 物理仿真中重放 70 帧动作，物体被**稳定抬升至少 30 cm** 并保持到结束（细节见第 5 节）。

## 2. 数据从哪来、长什么样

### 2.1 源数据：GraspM3 抓取轨迹

每个物体一个 `.npy` 文件，内含三样东西：

```
{
  "grasp_seqs": 形状 (20, 70, 28) 的数组,
  "obj_rotmat": 形状 (20, 3, 3) 的数组,
  "obj_scale":  形状 (20,) 的数组,
}
```

- `grasp_seqs`：**20 条抓取轨迹**。每条轨迹 = **70 帧 × 28 维**。28 维 = 手腕位置(3) + 手腕姿态欧拉角(3) + 22 个手指关节角。70 帧按 20 Hz 播放 = 3.5 秒的一段"伸手—抓—抬起"动作。
- `obj_rotmat` / `obj_scale`：物体在世界里的旋转和缩放（物体静止放在桌上）。
- 一个重要的坐标约定：源轨迹的平移以参考点 `[0,0,1]` 为原点，所以程序里统一给 z 加 0.4 的偏移，让手和物体处在同一坐标系。

### 2.2 物体模型：COACD 分解

物体网格不是一张完整的皮，而是被 COACD 算法切成**一堆凸块**（`coacd/decomposed.obj`）。物理引擎只用这些凸块算碰撞——快且稳定。

### 2.3 三只目标手的"说明书"：URDF

URDF 是机器人描述文件，告诉程序：手有哪些连杆（骨头）、哪些关节（活动处）、每个关节能转多少度（上下界）、哪个关节跟随哪个（mimic）。所有方法的第一步都是解析 URDF，拿到关节名、关节边界和"正向运动学"模型（**正向运动学 = 给定所有关节角，算出每个指尖在世界中的位置**，缩写 FK）。

### 2.4 关键点配置：语义对应表

为了把 Shadow 和目标手联系起来，项目手工定义了 **15 对语义关键点**（`configs/*_keypoint_map.json`）：掌心、四根手指的近端/中段/指尖、拇指中段/指尖。例如"Shadow 的食指指尖 ↔ XHand 的食指指尖"。这些配置是绝对点方法的地基，也是所有几何评测的统一口径。

### 2.5 冻结的数据清单：manifest

manifest 是 JSON 文件，**冻结**了"用哪些物体、哪些轨迹做实验"：50 个类别、每类 1 条轨迹（50 集用于方法筛选），或 50 类 × 2 物体 × 10 条（正式 1000 集）。冻结的意义：所有方法在同一批轨迹上对比，且筛选过程中**绝不偷看正式测试集**（防止调参作弊）。

## 3. 通用 pipeline：五步

所有方法都走同一条流水线：

```text
① 读源数据          ② 重定向（核心：28维→目标手D维）   ③ 物理重放
   .npy + URDF ──→      逐帧优化生成候选轨迹      ──→   Isaac Gym 里真的执行
        │                      │                          │
        │                      │                          ↓
        └──────────── ⑤ 配对比较 ←────────────── ④ 评测：成功/失败 + 失败原因
```

**② 重定向**是所有方法的分水岭，第 4 节逐手讲。**③ 物理重放**对所有方法完全相同：把生成的关节轨迹按 20 Hz 输入仿真（60 Hz 物理，每帧执行 3 步），手指由 PD 控制器（弹簧-阻尼：刚度 120、阻尼 5）驱向目标角度，物体受重力、碰撞、摩擦力自由运动。**④ 评测**见第 5 节。**⑤ 配对比较**：新旧方法在同一批轨迹上逐条对比，统计"新增几条、丢失几条"，用 McNemar 检验判断差异是否可信。

**生成与评测是分离的**：数学上算出的轨迹只是"候选"；只有物理重放成功抬起的才算数。

## 4. 三只手的最终方法

### 4.1 XHand（12 自由度）：分指段向量 + 捏合 α 混合

**成绩：50 集 32/50（官方基线 27/50，+5）**

#### 思路：为什么不直接对齐关键点？

早期方法让"Shadow 食指指尖的位置 = XHand 食指指尖的位置"（绝对点匹配）。问题：两只手的手指长度、骨节比例不同，硬凑位置会让手指折成不自然的形状；而且**姿势像不等于抓得住**。

#### 向量表征：匹配"关系"而不是"位置"

向量 = 两个关键点的**差**（方向和长度）。方法改成匹配：

- **掌心→指尖向量 ×5**：每根手指的指尖相对掌心的方向和距离（权重 1.0）
- **掌心→中段向量 ×5**：手指中间那节的弯曲形状（权重 0.5）
- **中段→指尖的方向向量 ×5**：指尖"指向哪里"（权重 5.0）——这个方向项专门防止"指尖位置对了但指着奇怪的方向"的退化解

每个向量按两只手**零姿态（全张开）时的长度比**自动缩放——这样 Shadow 手指短、XHand 手指长时，目标长度自动放大，不需要人手调。

#### 捏合 α 混合：让抓取重点随动作自动切换

关键洞察（来自 AnyDexRetarget）：手在做**捏合**（拇指尖靠近某根指尖）时，那根手指的指尖位置比整体姿势重要得多。

实现是**闭式计算**，不增加优化难度：每帧量一下源手"拇指尖到每根指尖的距离 d"：

```
α = clamp((0.05 - d) / (0.05 - 0.025), 0, 1)
```

- 距离 ≤ 2.5 cm（明显在捏合）→ α=1：该指尖权重拉满
- 距离 ≥ 5 cm（张开状态）→ α=0：该指尖权重降到 0.6/0.5 倍，放松跟踪
- 中间平滑过渡

#### 优化过程：70 次小型求解

把 70 帧拆成 70 个独立小问题，逐帧用 SLSQP（一种带约束的梯度优化器）求解：

- **变量**：18 维 = 手指关节(12) + 手腕平移(3) + 手腕欧拉角(3)
- **目标函数**（越小越好）：
  - 向量匹配误差（Huber 损失——对大误差"打折"，防止个别不可达目标霸占优化）
  - 掌心位置锚定（手腕要跟着源手走，否则接近阶段会跑偏）
  - 中性姿态正则 0.0025（没事就保持自然张开，别乱弯）
  - 上一帧连续性 0.01（相邻帧动作要顺滑）
- **边界**：关节角限制在 URDF 允许范围内
- **热启动**：第 1 帧从零姿态开始，之后每帧从上一帧的解开始（既省时间又保连续）

**输入**：70×28 源轨迹 → **输出**：70×18 候选轨迹（手腕 6 + 关节 12）。

### 4.2 Linker O6（6 自由度）：向量 + α + 接触锚 + 抓握偏置 + 热启动

**成绩：50 集 13/50（原方法夹紧+3mm 8/50，+5）**

#### 6 自由度的困境

Linker O6 只有 **6 个电机**驱动 11 个手指关节：URDF 里写着 5 个 mimic 关系（例如某关节 = 另一关节 × 1.86 倍），优化时只优化 6 个"主动量"，其余由联动自动跟随。22 维源动作压进 6 维，任何单一技巧都不够——最终方法是**四个组件叠加**的产物，每个组件都是被实验验证过的增量：

#### 组件 1：分指段向量 + α（与 XHand 相同的思想）

Linker 手指只有两段（近端+远端），所以向量更少：掌心→指尖 ×5、掌心→近端 ×4、近端→指尖方向 ×5，加上同样的 α 捏合混合。单靠它只能到 4/50——手指"照着样子摆"了，但抓不住。

#### 组件 2：接触锚（+2 条）

**诊断发现**：向量法忠实复现了源手的弯曲程度，但 Linker 手指更长、几何不同——源手用"轻捏"能拿住的物体，Linker 必须"用力包住"才能形成持续接触（失败轨迹的接触步数只有成功者的 1/3）。

接触锚的做法：在**闭合阶段**，把源手**正在接触物体的指尖的世界位置**当作钉子，惩罚目标手指尖偏离这些位置。它逼着目标指尖走到"确实压住物体"的地方，而不是"看起来像"的地方。

> 有意思的规律：接触锚**只在 Linker（6 DOF）有效**。XHand、Wuji 上试过都变差——自由度够的手本来就能把指尖放对，硬钉反而过约束。

#### 组件 3：抓握偏置（+2 条）

接触锚还不够：源手有些轨迹本身屈曲很小（比如抓小盒子），照抄还是不闭合。抓握偏置在闭合+抬升阶段加一个**单侧拉力**：

```
loss += w × relu(目标角度 - 当前角度)²
```

relu 的直觉：**只惩罚"弯得不够"，绝不惩罚"弯得更多"**——它把手指往更深的屈曲方向推（目标剖面取自夹紧法的闭合姿态：各指 0.9–1.5 rad），但已经弯够的解不受影响。权重 8 是最优档（5 不够、10 会挤坏可达解）。

#### 组件 4：热启动（warm start）

第 1 帧不从零姿态开始，而从**夹紧法已生成的闭合姿态**开始优化——帮 SLSQP 避开"手指半开"的局部最优。

#### 阶段检测：三种时态自动切换

以上组件只在特定阶段生效，阶段从源数据自动推断：

- **接近（approach）**：指尖离物体还远 → 只做向量跟踪，手自然张开
- **闭合（close）**：至少 2 根指尖进入物体表面 2 cm 内 → 启动接触锚 + 抓握偏置
- **抬升（lift）**：手腕比最低点升高 3 cm → 保持闭合，锁定抓形

**输入**：70×28 源轨迹 + 物体网格（算接触用）→ **输出**：70×12 候选轨迹（手腕 6 + 主动关节 6）。

### 4.3 Wuji（20 自由度）：绝对点法 + 解剖约束 + 拇指零空间（n005）

**成绩：50 集 34/50**（向量族 33/50 统计平手，保留原方法）

#### 为什么 Wuji 保留点法

Wuji 有 20 个自由度、形态最接近 Shadow，**15 对绝对关键点匹配在这里没有被结构差异拖垮**——向量族拼尽全力也只追平。Wuji 的最终方法是在点法基础上做三处"外科手术"：

#### 手术 1：解剖约束（coupled_flexion）

**问题**：优化器发现 URDF 允许 PIP/DIP 关节**反向弯折**到 -28°，于是"掰手指"包物体——物理上能抓住（旧版 581/1000），但手指反弯的动作在视频里是断指的，真机也不可能弯过去。

**修复**：在优化边界里把 PIP/DIP 的下限从 -28° 收到 **-5°**，并加软约束 `DIP ≈ 2/3 × PIP`（正常手指的远端关节跟着近端按比例弯）。边界同步写进物理仿真——仿真里也掰不过去了。代价：成功率下降约 15 个百分点，换来的是轨迹"像真手"、能当策略学习的专家数据。

#### 手术 2：拇指零空间修复

**问题**：点法只给了拇指 2 个点（中段+指尖），却要定 4 个拇指关节——解不唯一，优化器找了个"指尖位置对、但拇指对折成 90°"的难看解（96% 的帧）。

**修复**：删掉错的"拇指中段绝对对应"，只保留**指尖位置**这一条硬信息，剩下的自由度在"零空间"里用两个软规则选解：**中性姿态正则**（没事就保持自然弯度）+ 时序连续。权重 0.05 是最小充分档。结果：90° 折角帧从 96% 降到 2.6%，指尖位置最大偏移不到 3 mm。

#### 手术 3：阶段化"提前闭合"实验（phase_open，最终未采用）

用户视频审查发现拇指在"物体还远"时就提前弯成 90°。修法是让拇指**接近阶段保持展开、接触前 8 帧才开始闭合**（phase_open，lead=8/settle=4）。手型完美了（90° 帧 0%），但物理成功率 13→12→30/50 一路小降——**早闭合其实是"承力提前量"**。按成功率优先原则，n005 保留，phase_open 作为消融写进报告。

**输入**：70×28 源轨迹 → **输出**：70×26 候选轨迹（手腕 6 + 关节 20）。解剖配置（`wuji_anatomy_coupled_v1.json`）作为参数传入并记入产物哈希。

## 5. 物理重放与评测口径

### 重放设置（三手统一）

- Isaac Gym + CPU PhysX：60 Hz 物理，每源帧执行 3 步（20 Hz 动作）
- 每帧给出手指目标角度，PD 控制器（刚度 120 / 阻尼 5）驱近
- 物体：COACD 凸块碰撞体，静止在桌面，受重力

### 成功判据（stable 30cm protocol v2）

物体相对落稳初态抬升 ≥ 30 cm，且**最后 30 个物理步**同时满足：

1. 高度保持 ≥ 30 cm（不是瞬间过线）
2. 回落：峰值 → 末段下降 ≤ 3 cm
3. 波动：末段高度震荡 ≤ 1 cm（物体在手里要稳，不能晃）
4. 接触：手物持续接触

### 运输质量（进阶任务的入场券）

成功轨迹还要通过"掌物相对运输"门：末段物体相对手掌的滑动/转动要小——**抓住的物体不能在手心里打滑**。通过这条门的轨迹才是"专家数据"，才能喂给策略学习。

## 6. 方法筛选方法论（本项目的工作方式）

1. **50 集先筛**：所有新方法先在冻结的 50 条轨迹上评估，绝不直接上 1000（太贵）
2. **配对比较**：同一批轨迹上新旧方法逐条对比，报告"新增/丢失/净变化 + McNemar p 值"
3. **归因优先**：新方法一轮失败不直接扔——先看接触步数、关节剖面、loss 分解找出原因（本项目真抓到过 bug：批处理入口的 `return [` 死代码让所有"接触/抓握"参数从未生效）
4. **优化 1–2 轮**：改权重、改热启动、修实现，接近现任就暂留
5. **横向选优 → 深入优化胜者 → 最后才碰 1000**

## 7. 名词表

| 名词 | 含义 |
|---|---|
| DOF / 自由度 | 独立可控制的关节数量（电机数） |
| FK / 正向运动学 | 给定关节角，算出各点世界坐标 |
| SLSQP | 带边界约束的梯度优化算法，逐帧求解用 |
| Huber 损失 | 误差大时按线性计、误差小时按平方计——抗"个别目标根本够不着"的干扰 |
| mimic 关节 | 一个电机通过连杆倍率带动多个关节（欠驱动） |
| warm start / 热启动 | 用上一个解（或现成的好解）作为本次优化的起点 |
| PD 控制 | 弹簧-阻尼式跟踪：力 = 刚度×角度差 + 阻尼×角速度 |
| manifest | 冻结的实验清单（物体、轨迹索引、哈希） |
| 30cm 稳定协议 | 本项目的成功判据（见第 5 节） |
| α 混合 | 按拇指-指尖距离自动切换"指尖精度/整体姿态"权重 |
| 接触锚 | 把源手接触点当钉子约束目标指尖 |
| 抓握偏置 | 单侧（只增不减）的屈曲拉力，relu 实现 |
| 解剖约束 | 禁止手指反向弯折的关节边界与协调关系 |
| 零空间 | 满足同一硬约束（指尖位置）的多个解构成的自由度，用软规则在其中选解 |
| McNemar 检验 | 配对二分类数据的显著性检验，判断"新增/丢失"是否可信 |
| 50 集 / 1000 集 | 方法筛选集（50 类各 1 条）/ 正式评测集（50 类×2 物体×10 条） |
