# 三只目标手准备度与补齐顺序

“有URDF”只说明我们知道手的机械结构；要完成考核，每只手必须依次通过四层准备。

| 层级 | 含义 |
| --- | --- |
| A. 手模型 | URDF、mesh、关节顺序、上下限和主动/跟随关系正确 |
| B. 动作翻译 | Shadow与目标手的掌心、五指关键点对应正确，优化器能输出70帧 |
| C. 物理执行 | Isaac Gym正确加载手和物体，轨迹维度、关节顺序、PD控制一致 |
| D. 批量评测 | 能批量重放、计算成功率、保存成功/失败轨迹和视频 |

## 实施顺序

### 1. XHand：冻结基准答案

- 核对12个关节名称和Isaac Gym中的执行顺序；
- 把Shadow与XHand每个匹配索引翻译成“掌心/哪根手指/哪个关节”；
- 可视化张开、闭合及一条完整轨迹；
- 已用CPU PhysX重放第一条参考结果；后续接入manifest获得多物体成功率。

XHand的作用是给后两只手提供“一个正确适配器应该长什么样”的模板。

### 2. Linker O6：先修关键点，再谈成功率

- 根据URDF和mesh，为掌心、拇指以及其余四指定义真正的局部参考点；
- 明确6个主动量如何生成5个跟随关节角；
- 可视化确认每个点位于预期手指，而不是只检查数组形状；
- 再运行关键点优化，比较修正前后的几何误差和动作连续性；
- 最后进入Isaac Gym重放。

目前这条链路已经完整跑通。v2不增加自由度，也没有按物理结果取并集，但开发集5/10在独立20条上只得到6/20；更简单的夹紧v1得到7/20。固定残差使FruitBasket一条成功变失败，自适应PD没有改变成功集合，因此正式主方法回退为夹紧v1和默认PD 120/5。独立20条已用于方法选择，正式heldout仍需单独报告。

### 3. Wuji：按统一接口新建完整链路

- 读取20个关节、上下限和五个指尖link；
- 建立与Shadow五指一一对应的关键点表；
- 复用统一优化器生成 `(N,70,26)`，其中26为手腕6维加手部20维；
- 从XHand任务复制通用物体、桌面、成功判据部分，只替换手资产、关节映射和控制参数；
- 加入批量评测和结果保存。

## 不能跳过的检查

- 同一根手指的关键点顺序必须从掌根到指尖一致；
- URDF解析器、优化输出和Isaac Gym的关节顺序必须按名称映射，不能依赖默认索引；
- mimic关节不能被当成独立动作输出；
- 数学损失低只说明匹配点接近，必须通过渲染和物理重放；
- 三只手使用相同物体、轨迹、物理参数和成功判据，才能公平比较。
