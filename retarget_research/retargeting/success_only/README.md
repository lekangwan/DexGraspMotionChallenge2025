# 成功率优先补救分支

这组脚本不参与当前正在运行的正式 Rank-5 任务，也不会修改其 CEM 核心。

目标只有一个：在统一成功判据下提高独立重放成功率。手型自然性只作为诊断信息，不再用于淘汰物理成功轨迹。

流程：

1. 当前 Rank-5 完成独立重放和 v3 审计；
2. `compare_formal_results.py`把它与旧高成功率基线按同一字段比较；
3. 若净提升不足，`prepare_failure_manifest.py`从旧基线中只抽取失败轨迹；
4. 以旧基线完整 NPY 为 warm start，只对失败轨迹运行后续物理优化；
5. 最终仍对全部 1000 条做一次独立重放，不能用 CEM 内部成功率代替结果。

失败子集不是事后拼接两种方法：同一算法先执行统一基线，已经成功便提前结束，失败才进入统一的二阶段优化。这是确定性的 early-exit 计算策略。

`run_confirmed_synergy_manifest.py`与当前正式runner隔离。它只处理失败子manifest：先使用CEM核心已有的单环境确认作为预筛，再默认把基线和候选各独立重放2次。候选必须每次都同时满足稳定成功和运输约束，且平均分超过安全边际，否则对应轨迹自动恢复为原始基线。每次确认的标量指标单独保存，支持断点续跑与事后审计。

`confirm_existing_candidates_manifest.py`用于挽救已经完成的CEM计算。它不重新搜索参数，只找出screen summary中参数非零的轨迹，在上一阶段基线和现有候选之间做重复确认，拒绝项恢复基线，未被CEM修改的轨迹原样复制。因此其成本与“真正修改的轨迹数”成正比，而不是再次处理全部1000条。
